# 🔌 API Testing Guide — FinOps AI
# How to Manually Run and Test Every Single API Endpoint

> This guide teaches you how to talk directly to the backend server —
> without using the frontend app at all.
> This is how real developers test and debug APIs.
>
> BEFORE YOU START: Make sure the backend is running:
>   cd backend
>   uvicorn main:app --reload --port 8000
>
> Then open http://localhost:8000/docs in your browser (Swagger UI)

---

# WHAT IS SWAGGER UI?

When you open http://localhost:8000/docs you see a beautiful page.
This is called Swagger UI — it was automatically generated by FastAPI
from your code. It shows every API endpoint and lets you test them
directly in the browser with a "Try it out" button.

You will use TWO methods to test the API in this guide:

  METHOD 1: Swagger UI  → Click buttons in the browser (easiest)
  METHOD 2: curl        → Type commands in the terminal (like a real dev)

What is curl?
  curl = "Client URL" — a command-line tool that sends HTTP requests.
  It's like a browser, but for the terminal. No clicking, just commands.

# ═══════════════════════════════════════════
# STEP 1 — Register a New User Account
# Endpoint: POST /auth/register
# ═══════════════════════════════════════════

## What this does:
  Creates a new user in the database.
  The first user registered automatically becomes ADMIN.

## Using Swagger UI:
  1. Go to http://localhost:8000/docs
  2. Click on "POST /auth/register"
  3. Click the "Try it out" button (top right of that section)
  4. In the "Request body" box, replace the example with:
       {
         "email": "myemail@example.com",
         "password": "mypassword123"
       }
  5. Click the blue "Execute" button
  6. Scroll down to see the Response

## Using curl (PowerShell):

  Invoke-WebRequest -Uri "http://localhost:8000/auth/register" `
    -Method POST `
    -ContentType "application/json" `
    -Body '{"email": "myemail@example.com", "password": "mypassword123"}'

## EXPECTED RESPONSE (200 OK):
  {
    "id": 1,
    "email": "myemail@example.com",
    "role": "admin"
  }

## WHAT TO NOTICE:
  - The response does NOT include your password (it's never sent back)
  - role="admin" because you are the first user
  - id=1 means you are user #1 in the database

## ERROR RESPONSES:
  400 → "Email already registered"   ← You tried to register the same email twice
  422 → "Validation error"           ← Your email format was wrong

# ═══════════════════════════════════════════
# STEP 2 — Login and Get Your Token
# Endpoint: POST /auth/login
# ═══════════════════════════════════════════

## What this does:
  Checks your email and password.
  If correct, returns a JWT "access token".
  You MUST save this token — you need it for ALL other requests.

## Using Swagger UI:
  1. Click "POST /auth/login"
  2. Click "Try it out"
  3. Fill in the form fields:
       username: myemail@example.com
       password: mypassword123
  4. Click "Execute"

  NOTE: The field is called "username" not "email" here.
        This is a standard OAuth2 requirement. Just put your email in it.

## Using curl (PowerShell):

  Invoke-WebRequest -Uri "http://localhost:8000/auth/login" `
    -Method POST `
    -ContentType "application/x-www-form-urlencoded" `
    -Body "username=myemail@example.com&password=mypassword123"

## EXPECTED RESPONSE (200 OK):
  {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJteWVtYWlsQGV4YW1wbGUuY29tIiwiZXhwIjoxNzI0MTY3MDAwfQ.abc123...",
    "token_type": "bearer"
  }

## IMPORTANT — SAVE YOUR TOKEN:
  Copy the "access_token" value. It is a long string starting with "eyJ..."
  You will need to paste this token for all the requests below.

  In Swagger UI: Click the "Authorize" button (top right of the page),
  paste your token, and click "Authorize". Now all requests will include it.

## WHAT DOES THE TOKEN CONTAIN?
  Paste your token at https://jwt.io/ to decode it.
  You'll see something like:
  {
    "sub": "myemail@example.com",
    "exp": 1724167000     ← Unix timestamp when token expires (24 hours)
  }

# ═══════════════════════════════════════════
# STEP 3 — Upload Billing CSV Data
# Endpoint: POST /billing/upload
# ═══════════════════════════════════════════

## What this does:
  Uploads a CSV file with cloud billing data.
  The backend reads each row and saves it to the database.
  This is the DATA that all other endpoints use.

## Requirements:
  Your CSV MUST have these columns:
    date         → e.g. 2024-08-01
    service      → e.g. EC2, S3, RDS, Lambda
    resource_id  → e.g. i-0a1b2c3d
    cost         → e.g. 24.50

  Optional columns (can be missing):
    instance_type       → e.g. m5.xlarge
    usage_hours         → e.g. 720
    avg_cpu_utilization → e.g. 12.5
    storage_gb          → e.g. 100

  A sample file is already in: backend/sample_billing_data.csv

## Using Swagger UI:
  1. First click "Authorize" and paste your token (from Step 2)
  2. Click "POST /billing/upload"
  3. Click "Try it out"
  4. Click "Choose File" → select backend/sample_billing_data.csv
  5. Click "Execute"

## Using curl (PowerShell):

  $TOKEN = "paste-your-token-here"

  Invoke-WebRequest -Uri "http://localhost:8000/billing/upload" `
    -Method POST `
    -Headers @{Authorization = "Bearer $TOKEN"} `
    -Form @{file = Get-Item ".\backend\sample_billing_data.csv"}

## EXPECTED RESPONSE (200 OK):
  {
    "filename": "sample_billing_data.csv",
    "rows_inserted": 500,
    "rows_failed": 0,
    "errors": []
  }

## WHAT TO NOTICE:
  - rows_inserted = how many data rows were saved to the database
  - rows_failed = how many rows had errors (hopefully 0)
  - errors = list of specific row errors (if any)

## ERROR RESPONSES:
  400 → "Please upload a .csv file"     ← You uploaded a non-CSV file
  400 → "CSV is missing required columns: ['cost', 'date']" ← Columns missing
  401 → "Could not validate credentials" ← You forgot to include the token!

# ═══════════════════════════════════════════
# STEP 7 — Get AI Cost Prediction
# Endpoint: GET /ai/prediction
# ═══════════════════════════════════════════

## What this does:
  Uses Linear Regression to predict how much you'll spend
  in the next N days based on your past spending trend.

## Parameters:
  horizon_days = how many days ahead to predict (default: 30)
  You can change this: 7, 14, 30, 60, 90

## Using Swagger UI:
  1. Click "GET /ai/prediction"
  2. Click "Try it out"
  3. In the "horizon_days" field, type: 30
  4. Click "Execute"

## Using curl (PowerShell):

  $TOKEN = "paste-your-token-here"

  # Predict next 30 days
  Invoke-WebRequest -Uri "http://localhost:8000/ai/prediction?horizon_days=30" `
    -Headers @{Authorization = "Bearer $TOKEN"}

  # Predict next 7 days
  Invoke-WebRequest -Uri "http://localhost:8000/ai/prediction?horizon_days=7" `
    -Headers @{Authorization = "Bearer $TOKEN"}

  # Predict next 90 days
  Invoke-WebRequest -Uri "http://localhost:8000/ai/prediction?horizon_days=90" `
    -Headers @{Authorization = "Bearer $TOKEN"}

## EXPECTED RESPONSE (200 OK):
  {
    "next_period_days": 30,
    "predicted_cost": 4320.50,
    "lower_bound": 3980.20,
    "upper_bound": 4660.80,
    "trend": "rising",
    "daily_avg_recent": 144.02
  }

## WHAT EACH FIELD MEANS:
  next_period_days  → the horizon you asked for (30)
  predicted_cost    → our best estimate of total spend next 30 days ($4,320)
  lower_bound       → optimistic scenario (if costs grow slower = $3,980)
  upper_bound       → pessimistic scenario (if costs grow faster = $4,660)
  trend             → "rising" / "falling" / "flat"
  daily_avg_recent  → your average daily spend over the last 7 days ($144)

## HOW TO READ IT:
  - predicted_cost is the middle estimate
  - The real cost will probably be somewhere between lower_bound and upper_bound
  - "rising" trend means you should investigate — costs are growing!

# ═══════════════════════════════════════════
# UNDERSTANDING HTTP STATUS CODES
# ═══════════════════════════════════════════

When you make an API request, the response always has a STATUS CODE.
It tells you if the request succeeded or failed:

  200 OK            → Success! Everything worked.
  201 Created       → Success! Something new was created.
  400 Bad Request   → You sent wrong data (e.g. invalid CSV, wrong format)
  401 Unauthorized  → You are not logged in / your token is missing or expired
  403 Forbidden     → You are logged in but don't have permission
  404 Not Found     → The endpoint URL doesn't exist
  422 Unprocessable → Your JSON is correct format but failed validation
  500 Server Error  → Something crashed inside the server (a bug!)

In Swagger UI, the status code appears next to the word "Code:" in the Response section.
In curl, it appears in the "StatusCode" field of the output.

# ═══════════════════════════════════════════
# UNDERSTANDING THE AUTHORIZATION HEADER
# ═══════════════════════════════════════════

Every protected endpoint (everything except /auth/register and /auth/login)
requires you to prove you are logged in.

You do this by sending a special HTTP "header" with every request:

  Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Breaking it down:
  "Authorization"   → the header name
  "Bearer"          → the type of token (means "I'm presenting this token")
  "eyJhbGci..."     → the actual JWT token (your identity proof)

In curl:  -Headers @{Authorization = "Bearer YOUR_TOKEN_HERE"}
In Swagger UI: Click "Authorize" button → paste token → click "Authorize"

What happens if you DON'T include it?
  → You get: 401 Unauthorized
  → {"detail": "Not authenticated"}

# ═══════════════════════════════════════════
# TROUBLESHOOTING COMMON PROBLEMS
# ═══════════════════════════════════════════

PROBLEM: curl: Could not connect to http://localhost:8000
SOLUTION: The backend is not running. Open a terminal and run:
          cd backend
          uvicorn main:app --reload --port 8000

PROBLEM: 401 Unauthorized on every request
SOLUTION: You forgot to include the Authorization header.
          Make sure you logged in first and are using the correct token.
          Tokens expire after 24 hours — login again if expired.

PROBLEM: 422 Unprocessable Entity
SOLUTION: Your request body (JSON) has wrong field names or types.
          Check the "Request body" schema in Swagger UI for the correct format.

PROBLEM: 400 "CSV is missing required columns"
SOLUTION: Your CSV file must have: date, service, resource_id, cost
          Open sample_billing_data.csv to see the correct format.

PROBLEM: /ai/waste returns empty array []
SOLUTION: No waste was found OR you haven't uploaded data yet.
          Upload sample_billing_data.csv first (Step 3 above).

PROBLEM: Token is "eyJ..." but I get 401
SOLUTION: Copy the FULL token — it's a very long string.
          Make sure there are no spaces or newlines in it.
